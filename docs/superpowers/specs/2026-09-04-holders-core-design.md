## 一行で

**価格を追うのをやめて、季節を読むための場所。**

ホルダーと DRep が「今、何に時間と一票を使えばいいか」を判断するための材料置き場。
ニュースサイトでもポートフォリオでもない。**台帳が主役。**

---

## 解決する問題

ホルダーのコミュニティは、放置すると次の順序で劣化する。

```
何も動いていない
  → 語ることがない
  → 「〇〇が実装に近い」「ベース開発はいい感じ」で空白を埋める
  → 不確定な未来が前面に出る
  → 誰かを応援するだけの場になる
  → 相場の調整で全部消える
```

原因は五つ。

1. **時間軸の混同** — 外因（規制・ETF）と内因（エコシステムの成熟）を同じ画面で語る
2. **更新圧** — 毎日更新する義務が、期待を生産する
3. **記憶の非対称** — 覚えている人は疲れて去り、発信し続ける側だけが残る
4. **資金と関与の不可視** — 誰がいくら得て何を納めたかを holder が確認できない
5. **執着** — 目的・論点・人が一点に固まり、外からは熱心なコミュニティに見える

## 設計原則

| # | 原則 | 意味 |
|---|---|---|
| 1 | **論説より計器を厚くする** | 文章量ではなくデータ量で勝負する。これが最上位 |
| 2 | **外因と内因を混ぜない** | 全チェーン共通の潮と、Cardano の根を同じ指標にしない |
| 3 | **確定した事実だけ載せる** | 予定・ロードマップ・匂わせは載せない |
| 4 | **めったに更新しない** | 更新圧が嘘を生む。変わった時だけ変わる |
| 5 | **無いものは「無い」と表示する** | 空白を期待で埋めない |
| 6 | **人ではなく形を記録する** | 意図を推測しない。攻撃に見えた瞬間に価値が消える |
| 7 | **属性は動かさない** | 人を変えようとせず、入口だけを変える |
| 8 | **成果の型を混ぜない** | 技術型と信頼型を同じ物差しで測らない。並べるが混ぜない |
| 9 | **一点に執着しない** | 偏りは自分で表示する |
| 10 | **器を先に作らない** | 中身のない層は「実装に近い」と同じ形。台帳から作る |

原則1と原則10が v1 からの追加であり、v2 の再編はこの二つから導かれている。

# 第1部 — LEDGER（本体）

事実だけを置く層。三つの計器が供給し、時間軸で追跡する。

## 三計器 — Cardano の三権

holder が知りたいのに知る手段がないのは、結局これ。

> **誰が、どういう資格で、いくら得て、その後どうしたのか。**

これが見えないから「なんとなく信用できない」か「なんとなく応援する」の二択になる。
分散化されたシステムでは権力は三箇所に分かれており、それぞれに計器を当てる。

| 権 | 何が動くか | 計器 | 状態 |
|---|---|---|---|
| **金** | Treasury / Catalyst の資金 | Catalyst まとめ | **未着手（Phase 1）** |
| **分散** | ステークとリレーの実態 | リレー健全性ランキング / SPO Onchain Alive | 既存 |
| **意思** | ガバナンスの投票 | DRep terminal / 評議会 | 既存 |

**ゼロから作るのではなく、統合が仕事。** 新規で必要なのは Catalyst まとめだけ。

三つとも holder が自分で確認できる形で出す。
「このサイトがそう言っている」ではなく「一次情報がここにある」。

### Catalyst まとめが最重要な理由

三計器のうち、**唯一「時間の経過」を追える計器**だから。
SPO health と DRep terminal は「今」のスナップショット。Catalyst だけが段階を実データで追える。

---

## 段階 ①〜④

誤差が生まれる最大の原因は、段階の混同。**全ての項目に段階番号を付す。**

```
① 提案する      ← 誰でもできる。資金はまだ無い
② 採択される    ← ここで初めて資金が出る
③ 納品される    ← 資金が出ても完成するとは限らない
④ 使われる      ← 完成しても使われるとは限らない
```

①は「資金が無いから欲しい」という宣言であり、実行の反対側にある。
しかし①の時点で「Cardano が◯◯をやる」として拡散され、期待値が上がる。

**番号を付けるだけで、期待の大半は自然に沈む。**

---

## 誤差の型

| 型 | 形 | データでの現れ方 |
|---|---|---|
| 提案の誤読 | ①が④として拡散される | `not_approved` / `over_budget` |
| 匂わせ | 名前を出さずに大型提携を示唆 → 起きない | 手動記録 |
| 納品後の空白 | ③まで行ったが④が無い | `complete` かつ overlay の `used` 未記入 |
| 静かな消滅 | 期限を過ぎ、失敗の発表すらされない | **`status: terminated` / `paused`**（実測8件） |
| 取り下げ | 本人が引っ込めた。不採択とは別 | **`withdrawn`**（実測6件） |
| **型の不一致** | 技術型として申請し、信頼型の成果を納める | 手動記録 |
| **実現** | ①→④まで通った | `status: complete` + overlay の `used` |

**「静かな消滅」はデータに存在した。** 全件を数えて初めて出てきた（216件サンプルには1件も入っていなかった）。
`terminated` / `paused` / `withdrawn` を「単に不採択」と同じ①に潰してはいけない。段階とは別の軸 `outcome` として持つ。

**「実現」を同じ精度で記録することが台帳の信用の源。**
全部が嘘だと言いたいわけではない。通ったものも同じ精度で記録するから台帳が信用される。

### 資金取得後の分岐

| 型 | 形 | 見え方 |
|---|---|---|
| フェードアウト | 資金取得後、静かに消える | 報告が止まる。失敗の宣言もない |
| 実績なき継続 | 実績が無いまま活動と発信を続ける | 提案は出続けるが納品は積み上がらない |

どちらも公開データだけで追える。人物評は不要。
「提案数 ／ 採択数 ／ 納品報告 ／ その後の提案」を並べるだけで形が出る。

## 出力① — 形ごとの的中率

台帳が溜まると、**今の話に確率が付く**。

```
匂わせ型
  過去の事例      14件
  実現            2件
  縮小して実現     1件
  静かに消滅      11件
```

予測ではなく形の履歴。信じるかどうかは本人が決める。**サイトは判断しない。**

## 出力② — 初出年

全ての話題に初出年が付く。

> この話、初出2021年。以降①で3回。④到達なし。

新規ホルダーが「新しい話」だと思ったものが、実は5年目だと分かる。
**新規が、長期ホルダーの記憶を最初の日から持って始められる。**

## 出力③ — 参加の集中度

分散の実態は名目上の分散ではなく、**実際に手を動かしている人数**。

| 領域 | 測るもの | 計器 |
|---|---|---|
| 金 | 提案者の顔ぶれの固定度。常連比率 | Catalyst まとめ |
| 分散 | 上位何社でステーク何％か | SPO health |
| 意思 | 投票 DRep 数。上位何人で投票力何％か | DRep terminal |

「分散しているはずのシステムで、実際に動いているのは同じ数人」が数字で出る。
批判ではなく**分散化の現在地**であり、価値が上がる余地がどこにあるかの地図。

## 出力④ — 成果の型

各項目に型を付す。混ぜない、並べる。

```
[技術型] ◯◯   稼働中    拡散可能性 ○
[信頼型] ◯◯   4年継続   再現性 △（主宰者依存）
```

### 二つの資本

| | 技術型 | 信頼型 |
|---|---|---|
| 資本 | 動くもの | 人からの信用 |
| 減価 | しない | **する（発信を止めると減る）** |
| 過去の扱い | 積み上がる | **風化したほうが有利** |
| 批判への反応 | 反証すればいい | **資本の毀損になる** |

「過去が風化したほうが有利」は悪意ではなく**資本の性質**。
信頼型は発信を止めた瞬間に資本が減るため止められない。ポジティブでいることも親切であることも演技ではなく業務。技術型は黙っていてもコードが証明するが、信頼型にはそれがない。

構造として説明がつけば、人を責める必要が消える。

**信頼型は悪ではない。** 翻訳・コミュニティ運営・教育・新規への説明は分散化に必要。技術的成果物が出ないだけ。ここを外すと技術至上主義になる（＝執着の別の形）。
問題は型が悪いことではなく、**二つの型を同じ物差しで測っていること。**

### 信頼型の指標

| 指標 | 測るもの |
|---|---|
| 継続 | 何年続いているか |
| 到達 | 何人に届いたか |
| **再現性** | **その人がいなくても回るか** |

三つ目が本命。成果が本物なら**仕組みが残って本人が不要になる**。
本人が抜けると止まるなら、資本は個人に留保されエコシステムに蓄積されていない。
技術型の「動くものが残る」と同じ基準で、型を跨いで公平に測れる。

### 拡散可能性

技術型の評価軸はスペックではなく **説明の短さ**。

| | 拡散できる | 拡散できない |
|---|---|---|
| 例 | 「これで◯◯が今できる」 | 「◯◯が実装に近い」 |
| 状態 | 動いている | 予定 |
| holder の言葉 | 事実 | 期待 |

調整局面で残るのは性能が高いものではなく、**holder が他人に一息で説明できるもの**。
説明できないものは、持っている本人も信じきれていないため真っ先に手放される。

### 型の不一致は制度側の穴として書く

```
宣言した型   「◯◯を開発します」（技術型の言葉）
       ↓ 採択
実際の成果   啓発活動・イベント・発信（信頼型の成果）
```

**納品したかどうかではなく、約束した種類のものを納品したか。**
「静かな消滅」より見つけにくい。活動は活発で報告も上がる。ただ種類が違う。
holder が「開発が進んでいる」と思い続けるのは、ここで型が入れ替わっているから。

Catalyst の評価軸が技術寄りなら、**信頼型は技術の言葉で申請するしかない**。
型の不一致は申請者の問題であると同時に、**制度が信頼型の枠を持っていないことの症状**。
誰かを責めるためではなく制度側の穴を示すために書く。そのほうが台帳として強い。

## 記憶の外部化

### 忘却には利害がある

```
覚えているホルダー          発信資源を持つ側
─────────────          ─────────────
記録を残す動機なし          発信は業務の一部
発信は無報酬               出ていかない
疲れて出ていく             毎年新規が入ってくる
```

**悪意を仮定する必要はない。** この構造なら時間が経つほど過去は薄くなる。
記憶が個人の中にしか無い限り、風化する側が必ず負ける。

### 不信感 → 記録への変換

| | 感情のまま | 台帳に載せた後 |
|---|---|---|
| 形 | 「信用できない」 | 「2022年のこの件、①で止まった。リンク」 |
| 反論 | 「ネガティブだ」で処理される | 事実の検証しかできない |
| 寿命 | その人が去れば消える | 残る |

慰めるのではなく、**その人の記憶を資産として回収する。**

### 記憶の寄贈

```
提出できるもの： いつ / 何が言われたか / 一次情報のURL / その後どうなったか
提出できないもの： 出典のない記憶、意図の推測、人物評
```

検証を通ったものだけが台帳に載る。
**覚えている人が出ていく理由がひとつ減る。**「誰も覚えていない」が消えるから。

---

## 書き方の規律

台帳が攻撃に見えた瞬間に価値が消える。**記録装置に徹する。**

- 人ではなく形を記録する。誰が悪いかは扱わない
- 意図を推測しない。書くのは「言われたこと」と「起きたこと」だけ
- 一次情報のリンクを必ず付ける。検証可能でないものは載せない
- 結果が出ていないものは「保留」のまま置く。決めつけない
- 感情語を使わない。淡々と並べるほど強い
- 実現したものも同じ丁寧さで記録する
- 反論を受け付ける。各項目に当事者からの補足を並置できる
- 台帳自身の誤りも記録する。訂正履歴を消さない
- 成果の型を判定するが、優劣は付けない
- 型の不一致は制度側の穴として書く。申請者個人の責に帰さない

# 第2部 — MAP（読み方）

**年〜季節でしか変えない層。** ここを月次で更新し始めたら設計が壊れている合図。

## TIDE — 潮位（外因）

CLARITY法案、ETF、金利、各国規制。

- 速い（数週間〜数ヶ月）／ 外から来る（制御不能）
- **全チェーンに等しくかかる = ここで差はつかない**

**表示**: 潮位のみ。中身の良し悪しは評価しない。
**更新**: 事件単位（年に数回）。ETF承認や法案可決のような**離散イベントでのみ動かす**。
主観で「今は高い」と書かない。書けるのは「何が起きたか」だけ。

## 交点 — 潮が満ちた時、根は育っていたか

```
潮が来る  →  全部が上がる  →  調整が入る
                                  ↓
                      ここで「選ばれるもの」と「戻るもの」に分かれる
                                  ↓
              分けるのは、根が育っていたかどうか
```

上げ相場では全部が上がるから根の差は見えない。**調整で初めて見える。**
だから調整の前に根を見ておく必要がある。それが LEDGER の存在理由。

## FUEL — 六燃料と他チェーン

盛り上がりを種類で分解する。「盛り上がっている / いない」の一次元化を拒否する。

| 燃料 | 中身 | 届く属性 |
|---|---|---|
| 制度 | ETF、法案、規制 | 信念型・相場型 |
| ファンダメンタル | 実利用、採用、稼働数字 | 調査型・信念型 |
| 提携 | 誰と組んだか | 調査型・発見型 |
| 資金調達 | VC、Treasury配分、資金の流れ | 調査型・発見型 |
| 実装 | 実際に動き出したもの | 参加型・運用型 |
| 物語／投機 | ミーム、ナラティブ、勢い | 相場型・発見型 |

```
          制度  ファンダ  提携  資金調達  実装  物語
BTC        ●     ○       ·     ·       ·     ○
ETH        ●     ●       ○     ○       ○     ·
SOL        ○     ○       ○     ●       ○     ●
Base       ·     ○       ○     ○       ●     ●
Cardano    ○     ○       ·     ○       ●     ·
```

**粒度は一般的な動きでよい。ニュース精度は不要。**
目的は移動の促進ではなく**自分の属性の相対化**。ほとんどのホルダーはこれを見ても移動しない。移動しないと分かった上で置く。それが誠実。

弱点も隠さず出す（例: Cardano の物語欄が薄い）。弱点の告白ではなく地図。

**更新**: 年単位。性格の地図であり速報ではない。

## 視野の分布 — 偏りの指標

FUEL をそのまま偏りの指標に転用する。

```
点灯 1/6  → 一点集中。他が見えていない
点灯 3/6  → 健全
点灯 5/6  → 過熱
```

「盛り上がっている」の裏返しが「一箇所しか語られていない」であることを、同じ図で見せる。

# 第3部 — YOU（入口）

**薄い層。** ここで月次の編集作業を発生させない。属性ごとに LEDGER のどこを見るかを示すだけ。

## 読者は二人

| 読者 | 問い |
|---|---|
| **holder** | 今どう関わればいいか |
| **DRep** | この一票をチェーン全体の中でどう置くか |

**同じ材料で、違う判断をする。** サイトはどちらにも答えを出さない。材料を並べるだけ。

## holder の属性

属性は移動しない。相場が変わっても向き不向きは変わらない。

| 属性 | 楽しいこと | 動かない理由 |
|---|---|---|
| 参加型 | 委任・投票・Treasury・仕組みに関わる | 値動きに興味がない |
| 調査型 | 提携・資金調達・採用事例を読み解く | 数字と物語を繋ぐのが快感 |
| 運用型 | 利回り、流動性、資産を働かせる | 遊ばせるのが嫌 |
| 発見型 | 誰も見ていない新プロジェクト | 早さそのものが報酬 |
| 相場型 | 値動き、PERP、ヘッジ | 動いていないと退屈 |
| 信念型 | 持ち続ける。何もしない | 触るほど下手になると知っている |

相場型に「投票しよう」と言っても届かないし、信念型に「PERPで」と言うのは害。
**サイトの仕事は属性を変えることではなく、属性ごとに違う入口を用意すること。**

### 「何もない時期」は存在しない

「誰かを応援しよう、いつか上がる」に落ちない答えを用意する。
答えは **応援ではなく参加**。

分散化されたシステムでは holder は観客ではなく構成要素そのもの。
委任先を選ぶ、投票する、Treasury の使い道を決める、実際に使う。
**これは暇つぶしではなく、分散の実態そのものを太らせる行為。**

価値は開発者が上げるのではなく、**分散の実態が濃くなることで上がる**。
そして分散の実態は holder の行動そのもの。
潮を待つ時期＝根を太らせる時期として名前を与える。

## DRep という読者

### 「一つの提案に一つの答え」

```
提案が来る → その提案だけを見る → 今ある情報と価値観で判断 → 次へ
```

一件ずつ処理はされ、投票率も上がる。だがこれは判断ではなく**採点**。
Treasury は有限で、**一つ通すことは他を通さないこと**。チェーン全体の市場環境、技術の優先順位、マーケティング上の効果を横断して初めて「今これに配分すべきか」が決まる。個別に採点している限り、その問いは一度も立たない。

**やっているように見えてやっていない、の正体。**

### 投票数では測れない

| 測ってはいけないもの | 理由 |
|---|---|
| 投票数 | 全件に票を入れても、全件を個別採点しただけかもしれない |
| 投票率 | 活動量であって判断の質ではない |
| 賛成率 | 高くても低くても、それだけでは何も言えない |

測るのは **rationale（投票理由）という文書の性質**。公開データであり、意図の推測ではない。

| 軸 | 見るもの |
|---|---|
| 理由の有無 | rationale を書いているか |
| 参照範囲 | 提案単体だけか、他の提案・Treasury 全体・市場文脈に触れているか |
| **機会費用** | **「これを通すと何が通らないか」に言及しているか** |
| 一貫性 | 過去の投票と同じ基準が使われているか |
| チェーン外の視野 | 他チェーンの動向や市場環境が判断に入っているか |

三つ目が本命。「一つの提案に一つの答え」の反対語は**提案をポートフォリオとして見ること**。

### 責めずに環境を作る

**技術とマーケティングとチェーン全体の市場を、一人で全部見られる人間はほとんどいない。**
それを要求する制度のほうに無理がある。能力の問題ではなく、**材料が一箇所に無いことの問題**。

| DRep が判断に必要なもの | 供給する層 |
|---|---|
| 市場全体は今どこにいるか | MAP / TIDE |
| 他チェーンは何で動いているか | MAP / FUEL |
| 金は今どこに流れているか | LEDGER / Catalyst まとめ |
| 分散は実際どうなっているか | LEDGER / SPO health |
| 過去の同種の提案はどうなったか | LEDGER / 誤差の台帳 |
| この提案者は前回何を納めたか | LEDGER / Catalyst まとめ |

**六つとも揃う場所が今どこにも無い。** それを作ることが holders CORE の実体。

rationale の五軸は出すが、目的は順位付けではなく**何を書けば良い rationale になるかの基準を示すこと**。基準が見えれば、書ける人は書くようになる。
台帳の規律と同じ。**記録装置に徹し、環境を整える。**

# 執着への自戒

**このサイトの名前が holders CORE である時点で、目的の固着が起きる。**

```
holder のために
  → holder が喜ぶ情報を出す
  → 不都合な数字を弱める
  → 無いものを「無い」と言えなくなる
  → 原則5が死ぬ
```

**holder のために作るが、「holder のために」とは言わない。**
サイトは holder の味方をするのではなく、holder が見るべきものを見せる。時にそれは holder に不利な数字になる。

### 執着の三形態

| 形 | 症状 | 起きること |
|---|---|---|
| 目的の固着 | 「holder のために」が旗印になる | 都合のいい情報しか載らない |
| 論点の固着 | governance だけを語り続ける | 他の領域が見えなくなる |
| 人の固着 | 同じ顔ぶれだけが活動する | 名目は分散、実態は少数 |

三つとも外からは「熱心なコミュニティ」に見える。だから止まらない。

### 仕様に入れる自戒

- **LEDGER が薄く MAP が厚くなったら退化の合図。** 比率を監視する
- 誤差の台帳は面白いので肥大しやすい。肥大した瞬間に告発サイトになる
- 三計器のうち一つだけを更新し続けていたら偏っている
- 「holder のために」を文言として掲げない
- **偏りの指標を自サイトにも適用する。** どの層・どの計器を何回更新したかを自分で表示する

最後が要。**サイトが自分の偏りを自分で表示する。**
執着を止める唯一の方法は、執着していることが自分に見えること。

# 更新頻度の設計

**更新頻度が低いことが、このサイトの品質保証。**

ニュースサイトは毎日更新しないと死ぬため、載せるものが無い日も載せる。
その埋め草が「〇〇が実装に近い」になる。**更新義務が期待を生産する。**

| | ニュースサイト | holders CORE |
|---|---|---|
| 価値 | 新しさ | 構造 |
| 更新 | 毎日必須 | 変わった時だけ |
| 空白 | 埋める | そのまま置く |
| 読み方 | 毎日見る | 迷った時に見る |

| 層 | 更新頻度 | 駆動 |
|---|---|---|
| LEDGER / Catalyst | ファンド単位 | データ |
| LEDGER / SPO health | エポック単位 | データ |
| LEDGER / DRep | 議案単位 | データ |
| LEDGER / 誤差台帳 | 事例確定時 | データ |
| MAP / TIDE | 事件単位（年数回） | 離散イベント |
| MAP / FUEL | 年単位 | 編集 |
| YOU | 不変 | — |

**編集作業が発生するのは MAP / FUEL の年1回だけ。** ここが v1 からの最大の変更点。
月次の編集を一切設計に入れない。**一人で維持できることが要件。**

先月と同じなら「先月と同じです。潮を待つ時期です」とだけ出る。
**その静けさが holder にとって一番の情報になる。**

# 実装フェーズ

## Phase 1 — Catalyst まとめ（単体）

**これだけを作る。他は作らない。**

理由：

- 三計器で**唯一 誤差の台帳に実データを供給できる**器
- SPO health と DRep terminal は既にある。**新規で必要なのはこれだけ**
- 器を先に作ると中身のない箱ができる。**それがこのサイトの最も嫌う形**（原則10）

スコープ：

- **Catalyst 提案の全件を対象**（Fund 2〜15、11,385件、提案者 5,699名）
- 段階①〜④の記録
- 提案数 / 採択数 / 納品報告 / その後の提案 の一覧
- 一次情報リンク必須（全件がリンクを持つことを実測で確認済み）
- 成果の型（技術型 / 信頼型）の付与
- 日本語圏は**絞り込みの一つ**として持つ。デフォルト表示ではない

**訂正 2026-09-04 — 当初「日本語圏に絞る」としていた方針を撤回する。**

理由が二つある。

一つ目は思想の矛盾。日本語圏だけを扱うサイトは、**このサイトが批判している「特定のコミュニティしか活動しない」そのもの**になる。原則9（一点に執着しない）に自分で反していた。holder が判断に使う材料が自分のコミュニティの中で閉じていたら、それは地図ではなく鏡になる。

二つ目は、絞る技術的理由が実測で消えたこと。表示用の細い記録なら1件498バイト、全体で5MB。Fund 単位に分割すれば最大797KB（Fund 13）で静的サイトとして普通に成立する。全11,385件がすでに一次情報リンクを持つため、絞らなくても「リンクのないものは載せない」規律は守れる。

そして全件にしたことで、絞っていたら見えなかったものが見えた（次項）。

## Phase 2 — LEDGER 統合

Catalyst まとめが動いたら、SPO health と DRep terminal を同じ台帳の下に並べる。
形ごとの的中率、初出年、参加の集中度の出力を追加。

## Phase 3 — MAP

TIDE と FUEL。**台帳を作ってみないと MAP に何を書くべきかも分からない。**

## Phase 4 — YOU

属性別の入口と、DRep 向けの rationale 五軸。記憶の寄贈の受け口。
