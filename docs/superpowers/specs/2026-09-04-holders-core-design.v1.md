# holders CORE — 設計書

*Created: 2026-09-04*
*Status: 設計確定 / 実装計画未着手*

---

## 一行で

**価格を追うのをやめて、季節を読むための場所。**

ホルダーが「今、何に時間を使えばいいか」を判断するための材料置き場。
ニュースサイトでもポートフォリオでもなく、その中間にある構造の地図。

---

## 解決する問題

ホルダーのコミュニティは、放置すると次の順序で劣化する。

```
何も動いていない
  → 語ることがない
  → 「〇〇が実装に近い」「ベース開発はいい感じ」で空白を埋める
  → 不確定な未来が前面に出る
  → 誰かを応援するだけの場になる
  → 相場の調整で全部消える
```

原因は五つ。

1. **時間軸の混同** — 外因（規制・ETF）と内因（エコシステムの成熟）を同じ画面で語る
2. **更新圧** — 毎日更新する義務が、期待を生産する
3. **記憶の非対称** — 覚えている人は疲れて去り、発信し続ける側だけが残る
4. **資金と関与の不可視** — 誰がいくら得て何を納めたかを holder が確認できない
5. **執着** — 目的・論点・人が一点に固まり、外から見ると熱心なコミュニティに見える

holders CORE はこの五つを、構造で止める。

---

## 設計原則

| # | 原則 | 意味 |
|---|---|---|
| 1 | **TIDE と ROOT を混ぜない** | 外因と内因は同じ画面に置くが、決して同じ指標にしない |
| 2 | **FUEL を六種に分解する** | 「盛り上がっている / いない」の一次元化を拒否する |
| 3 | **属性は動かさない** | 人を変えようとせず、入口だけを変える |
| 4 | **確定した事実だけ載せる** | 予定・ロードマップ・匂わせは載せない |
| 5 | **めったに更新しない** | 更新圧が嘘を生む。変わった時だけ変わる |
| 6 | **無いものは「無い」と表示する** | 空白を期待で埋めない |
| 7 | **人ではなく形を記録する** | 意図を推測しない。攻撃に見えた瞬間に価値が消える |
| 8 | **一点に執着しない** | 六層のどれか、三計器のどれかに偏らない。偏りは自分で表示する |
| 9 | **成果の型を混ぜない** | 技術型と信頼型を同じ物差しで測らない。並べるが混ぜない |

## 全体構造 — 七層

```
┌────────────────────────────────────────────┐
│ TIDE         潮位（外因・全チェーン共通）         │
├────────────────────────────────────────────┤
│ FUEL         六燃料の点灯 ／ 他チェーン ／ 視野の分布 │
├────────────────────────────────────────────┤
│ YOU          属性別の入口                       │
├────────────────────────────────────────────┤
│ ROOT         動いている事実 ／ 参加の集中度        │
├────────────────────────────────────────────┤
│ INSTRUMENTS  三計器（金・分散・意思）             │
├────────────────────────────────────────────┤
│ ECHO         発言と実行の誤差（台帳）             │
├────────────────────────────────────────────┤
│ MEMORY       記憶の外部化（寄贈と検証）           │
└────────────────────────────────────────────┘
                      ↓
               自サイトの偏り表示
```

**六層は器、三計器が中身。** 計器だけだと数字の羅列になり、論説だけだと意見になる。

---

## 層1 — TIDE（潮位・外因）

**役割**: ブロックチェーン全体を上下させる力の現在位置を示す。

対象: CLARITY法案、ETF、金利、各国規制。

**性質**:
- 速い（数週間〜数ヶ月）
- 外から来る（制御不能）
- **全チェーンに等しくかかる = ここで差はつかない**

**表示**: 潮位のみ。中身の良し悪しは評価しない。「今どのあたりにいるか」だけ。

**更新頻度**: 事件単位（年に数回）。

---

## 層2 — FUEL（燃料の点灯状態）

**役割**: 盛り上がりを種類で分解し、Cardano と他チェーンを横並びにする。

### 六種の燃料

| 燃料 | 中身 | 届く属性 |
|---|---|---|
| 制度 | ETF、法案、規制 | 信念型・相場型 |
| ファンダメンタル | 実利用、採用、稼働数字 | 調査型・信念型 |
| 提携 | 誰と組んだか | 調査型・発見型 |
| 資金調達 | VC、Treasury配分、資金の流れ | 調査型・発見型 |
| 実装 | 実際に動き出したもの | 参加型・運用型 |
| 物語／投機 | ミーム、ナラティブ、勢い | 相場型・発見型 |

### 他チェーン横並び

```
          制度  ファンダ  提携  資金調達  実装  物語
BTC        ●     ○       ·     ·       ·     ○
ETH        ●     ●       ○     ○       ○     ·
SOL        ○     ○       ○     ●       ○     ●
Base       ·     ○       ○     ○       ●     ●
Cardano    ○     ○       ·     ○       ●     ·
```

**目的は移動の促進ではなく、自分の属性の相対化。**
ほとんどのホルダーはこれを見ても移動しない。移動しないと分かった上で置く。

**粒度**: 一般的な動きでよい。ニュース精度は不要。
**更新頻度**: 年単位（性格の地図であり、速報ではない）。

弱点も隠さず出す（例: Cardano の物語欄が薄い）。弱点の告白ではなく地図。

---

## 層3 — YOU（属性）

**役割**: 属性ごとに違う入口を用意する。属性を変えさせない。

### 六つの属性

| 属性 | 楽しいこと | 動かない理由 |
|---|---|---|
| 参加型 | 委任・投票・Treasury・仕組みに関わる | 値動きに興味がない |
| 調査型 | 提携・資金調達・採用事例を読み解く | 数字と物語を繋ぐのが快感 |
| 運用型 | 利回り、流動性、資産を働かせる | 遊ばせるのが嫌 |
| 発見型 | 誰も見ていない新プロジェクト | 早さそのものが報酬 |
| 相場型 | 値動き、PERP、ヘッジ | 動いていないと退屈 |
| 信念型 | 持ち続ける。何もしない | 触るほど下手になると知っている |

**表示**: 属性 × 燃料 の交差点に、その人の「今の楽しみ」がある。

```
調査型へ： 今月、提携と資金調達の動きはゼロ。読むものはない
発見型へ： 新規デプロイ3件。ただし全部小さい
参加型へ： 投票中の議案5件。ここは今動いている
```

**無いものを無いと言う。** 期待で埋めると人は消耗し、無いと言われると落ち着く。

**更新頻度**: 属性定義は不変。交差点の表示は FUEL に追従（月単位）。

---

## 層4 — ROOT（根の状態）

**役割**: Cardano の仕組みと現状を、事実だけで示す。

**性質**:
- 遅い（年単位）
- 内から育つ
- **ここでしか差はつかない**

### 載せるもの / 載せないもの

| 載せる | 載せない |
|---|---|
| 今この瞬間に動いているもの | ロードマップ |
| 稼働している数字 | 「もうすぐ」 |
| 実際に使える機能 | 誰かの発表 |
| 分散の実態 | 期待値 |

### 拡散可能性の評価軸

技術スペックではなく **説明の短さ** で評価する。

| | 拡散できる | 拡散できない |
|---|---|---|
| 例 | 「これで◯◯が今できる」 | 「◯◯が実装に近い」 |
| 状態 | 動いている | 予定 |
| holder の言葉 | 事実 | 期待 |

調整局面で残るのは性能が高いものではなく、**holder が他人に一息で説明できるもの**。
説明できないものは、持っている本人も信じきれていないため真っ先に手放される。

各項目に **拡散可能性 ○ / △ / ×** を付す。

### データ源

層5「INSTRUMENTS（三計器）」を参照。

### 参加の集中度

分散の実態は名目上の分散ではなく、**実際に手を動かしている人数**で測る。

| 領域 | 測るもの | 計器 |
|---|---|---|
| 金 | 提案者の顔ぶれの固定度。常連比率 | Catalyst まとめ |
| 分散 | 上位何社でステーク何％か | SPO health check |
| 意思 | 投票している DRep 数。上位何人で投票力何％か | DRep terminal |

「分散しているはずのシステムで、実際に動いているのは同じ数人」が数字で出る。
批判ではなく分散化の現在地であり、価値が上がる余地がどこにあるかの地図。

### 成果の型を明示する

ROOT の各項目には型を付す。混ぜない、並べる。

```
[技術型] ◯◯   稼働中    拡散可能性 ○
[信頼型] ◯◯   4年継続   再現性 △（主宰者依存）
```

**更新頻度**: 動いた時だけ。ROOT に一行増えることが事件になる。

## 層5 — INSTRUMENTS（三計器）

**役割**: 「誰が、どういう資格で、いくら得て、その後どうしたのか」を測る。

holder がこれを知る手段を持たないため、「なんとなく信用できない」か「なんとなく応援する」の二択になる。分散化されたシステムでは権力は三箇所に分かれており、それぞれに計器を当てる。

| 権 | 何が動くか | 計器 |
|---|---|---|
| **金** | Treasury / Catalyst の資金 | Catalyst まとめ |
| **分散** | ステークとリレーの実態 | SPO health check（リレー健全性ランキング / SPO Onchain Alive） |
| **意思** | ガバナンスの投票 | DRep terminal（評議会 / governance-humanism-action） |

三つとも既に存在するか作れる。**ゼロから作るのではなく、統合が仕事。**

### Catalyst まとめが最重要な理由

三計器のうち、**唯一「時間の経過」を追える計器**だから。
SPO health と DRep terminal は「今」のスナップショット。Catalyst だけが ①提案 → ②採択 → ③納品 → ④使用 の段階を実データで追える。

つまり **ECHO に実データを供給できる唯一の器**。
論説で「誤差がある」と言うのと、「Fund◯の採択◯件のうち④到達は◯件」と出すのは重さが違う。

### 追跡する分岐

資金取得後の分岐は主に二つ。どちらも公開データだけで追え、人物評は不要。

| 型 | 形 | 見え方 |
|---|---|---|
| フェードアウト | 資金取得後、静かに消える | 報告が止まる。失敗の宣言もない |
| 実績なき継続 | 実績が無いまま活動と発信を続ける | 提案は出続けるが納品は積み上がらない |

「提案数 ／ 採択数 ／ 納品報告 ／ その後の提案」を並べるだけで形が出る。

### 日本語圏に絞る

範囲の限定であると同時に精度の担保。

- 全体を追うと薄くなり、英語圏の既存ツールの劣化版になる
- 日本語圏なら提案・報告・その後の発信まで一次情報を全部追える
- 日本の holder が一番知りたいのは日本語圏の話

**全部を追わないことが品質になる。**

### 三計器が揃うと言えること

一つずつでは意見だが、三つ揃うと構造の証明になる。
「分散化された今、どのように価値が上がる可能性があるか」に、感想ではなく数字で答えられる。

三つとも **holder が自分で確認できる形** で出す。
「このサイトがそう言っている」ではなく「一次情報がここにある」。

### 各層への供給

| 層 | 供給元 |
|---|---|
| ROOT | 三計器すべて |
| ECHO | Catalyst まとめ（段階①〜④の実データ） |
| MEMORY | Catalyst まとめの履歴がそのまま風化防止装置になる |
| FUEL（資金調達欄） | Catalyst まとめ。「今月、金はどこへ流れたか」 |

**更新頻度**: 計器ごとに異なる。Catalyst はファンド単位、SPO health はエポック単位、DRep terminal は議案単位。

## 層6 — ECHO（発言と実行の誤差）

**役割**: 「何が起きると思われていて、実際どうだったか」を記録する台帳。

### 段階の明示

誤差の最大の原因は段階の混同。全ての話題に段階番号を付す。

```
① 提案する      ← 誰でもできる。資金はまだ無い
② 採択される    ← ここで初めて資金が出る
③ 納品される    ← 資金が出ても完成するとは限らない
④ 使われる      ← 完成しても使われるとは限らない
```

Catalyst / Treasury は①の時点で「決定事項」として拡散されやすい。
①は「資金が無いから欲しい」という宣言であり、実行の反対側にある。

**番号を付けるだけで、期待の大半は自然に沈む。**

### 記録する誤差の型

| 型 | 形 |
|---|---|
| 提案の誤読 | ①が④として拡散される |
| 匂わせ | 名前を出さずに大型提携を示唆 → 起きない |
| 納品後の空白 | ③まで行ったが④が無い |
| 静かな消滅 | 期限を過ぎ、失敗の発表すらされない |
| **型の不一致** | 技術型として申請し、信頼型の成果を納める（後述） |
| **実現** | ①→④まで通った |

**「実現」を同じ精度で記録することが台帳の信用の源。**

### 出力 — 形ごとの的中率

```
匂わせ型
  過去の事例      14件
  実現            2件
  縮小して実現     1件
  静かに消滅      11件
```

予測ではなく形の履歴。信じるかどうかは本人が決める。サイトは判断しない。

### ROOT との接続

ROOT の「予定は載せない」ルールが ECHO によって根拠を持つ。
ルールが誰かの意見ではなく、自分たちで取った記録になる。

**更新頻度**: 事例が確定した時のみ。ほぼ固定資産。書き換わらず、増える。

## 層7 — MEMORY（記憶の外部化）

**役割**: 忘却の非対称を止める。

### 問題の構造

```
覚えているホルダー          発信資源を持つ側
─────────────          ─────────────
記録を残す動機なし          発信は業務の一部
発信は無報酬               出ていかない
疲れて出ていく             毎年新規が入ってくる
```

**悪意を仮定する必要はない。** この構造なら時間が経つほど過去は薄くなる。
記憶が個人の中にしか無い限り、風化する側が必ず負ける。

### 不信感 → 記録への変換

| | 感情のまま | 台帳に載せた後 |
|---|---|---|
| 形 | 「信用できない」 | 「2022年のこの件、①で止まった。リンク」 |
| 反論 | 「ネガティブだ」で処理される | 事実の検証しかできない |
| 寿命 | その人が去れば消える | 残る |

不信感を持つ人を慰めるのではなく、**その人の記憶を資産として回収する。**

### 記憶の寄贈

```
提出できるもの：
  いつ / 何が言われたか / 一次情報のURL / その後どうなったか

提出できないもの：
  出典のない記憶、意図の推測、人物評
```

検証を通ったものだけが台帳に載る。

### 新規ホルダーへの効果

新規は毎年入ってくる。過去を知らないため、同じ話に同じように期待し、同じように削られる。
**世代ごとに記憶がリセットされるから、同じ形が何度でも通る。**

台帳があると全ての話題に **初出年** が付く。

> この話、初出2021年。以降①で3回。④到達なし。

**新規ホルダーが、長期ホルダーの記憶を最初の日から持って始められる。**

## 成果の型 — 技術資本と信頼資本

### 二つの資本

| | 技術型 | 信頼型 |
|---|---|---|
| 資本 | 動くもの | 人からの信用 |
| 成果 | 検証できる | 数えにくい |
| 減価 | しない（動き続ける） | **する（発信を止めると減る）** |
| 過去の扱い | 積み上がる | **風化したほうが有利** |
| 批判への反応 | 反証すればいい | **資本の毀損になる** |

「過去が風化したほうが有利」は悪意ではなく、**資本の性質**。
信頼型は発信を止めた瞬間に資本が減るため、止められない。ポジティブでいることも親切であることも演技ではなく業務。技術型は黙っていてもコードが証明するが、信頼型にはそれがない。

構造として説明がつくと、人を責める必要が消える。

### 信頼型は悪ではない

ここを外すと技術至上主義になる（＝執着の別の形）。
翻訳、コミュニティ運営、教育、イベント、新規への説明は実際に必要で、誰かがやらないと分散化は進まない。技術的成果物が出ないだけ。

**問題は型が悪いことではなく、二つの型を同じ物差しで測っていること。**

### 型の不一致 — 見つけにくい誤差

```
宣言した型   「◯◯を開発します」（技術型の言葉）
       ↓
採択される
       ↓
実際の成果   啓発活動・イベント・発信（信頼型の成果）
```

**納品したかどうかではなく、約束した種類のものを納品したか。**

「静かな消滅」より見つけにくい。活動は活発で報告も上がる。ただ種類が違う。
holder が「開発が進んでいる」と思い続けるのは、ここで型が入れ替わっているから。

### 制度側の穴として書く

責任を個人に置くとまた人物評になる。

Catalyst の評価軸が技術寄りに設計されていれば、**信頼型の活動は技術の言葉で申請するしかない**。翻訳やコミュニティ運営で正面から資金が取れないなら「◯◯プラットフォームを開発」と書くことになる。

型の不一致は申請者の問題であると同時に、**制度が信頼型の枠を持っていないことの症状**。
台帳はここまで書く。誰かを責めるためではなく制度側の穴を示すため。そのほうが台帳として強い。

### 信頼型を測る指標

| 指標 | 測るもの |
|---|---|
| 継続 | 何年続いているか |
| 到達 | 何人に届いたか（参加者数、翻訳数、閲覧数） |
| **再現性** | **その人がいなくても回るか** |

三つ目が本命。信頼型の成果が本物なら、**仕組みが残って本人が不要になる**。
本人が抜けると全部止まるなら、資本は個人に留保されたままでエコシステムに蓄積されていない。
技術型の「動くものが残る」と同じ基準であり、型を跨いで公平に測れる。

## 執着 — 視野が一点に固まる

### 三つの形

| 形 | 症状 | 起きること |
|---|---|---|
| 目的の固着 | 「holder のために」が旗印になる | holder に都合のいい情報しか載らなくなる |
| 論点の固着 | governance だけを語り続ける | 動いている他の領域が見えなくなる |
| 人の固着 | 同じ顔ぶれだけが活動する | 名目は分散、実態は少数 |

三つとも外からは「熱心なコミュニティ」に見える。だから止まらない。

### 偏りを数字にする

**視野の分布** — 六燃料のうち何個が点いているか。FUEL 層をそのまま偏りの指標に転用する。

```
点灯 1/6  → 一点集中。他が見えていない
点灯 3/6  → 健全
点灯 5/6  → 過熱
```

「盛り上がっている」の裏返しが「一箇所しか語られていない」であることを、同じ図で見せる。

**参加の集中度** — 層4 ROOT を参照。

### サイト自身が執着しないための規律

**このサイトの名前が holders CORE である時点で、目的の固着が起きる。**

```
holder のために
  → holder が喜ぶ情報を出す
  → 不都合な数字を弱める
  → 無いものを「無い」と言えなくなる
  → 原則6が死ぬ
```

**holder のために作るが、「holder のために」とは言わない。**
サイトは holder の味方をするのではなく、holder が見るべきものを見せる。時にそれは holder に不利な数字になる。

仕様に入れる自戒：

- 六層のどれか一つを厚くしすぎない。特に ECHO は面白いので肥大しやすく、肥大した瞬間に告発サイトになる
- governance に寄らない。三計器のうち一つだけを更新し続けていたら偏っている
- 「holder のために」を文言として掲げない
- **偏りの指標を自サイトにも適用する。** どの層・どの計器を何回更新したかを自分で表示する

最後の一つが要。**サイトが自分の偏りを自分で表示する。**
執着を止める唯一の方法は、執着していることが自分に見えること。

## 書き方の規律

台帳が攻撃に見えた瞬間に価値が消える。記録装置に徹する。

- 人ではなく形を記録する。誰が悪いかは扱わない
- 意図を推測しない。書くのは「言われたこと」と「起きたこと」だけ
- 一次情報のリンクを必ず付ける。検証可能でないものは載せない
- 結果が出ていないものは「保留」のまま置く。決めつけない
- 感情語を使わない。淡々と並べるほど強い
- 実現したものも同じ丁寧さで記録する
- 反論を受け付ける。各項目に当事者からの補足を並置できる
- 台帳自身の誤りも記録する。訂正履歴を消さない
- 成果の型（技術型／信頼型）を判定するが、優劣は付けない
- 型の不一致は制度側の穴として書く。申請者個人の責に帰さない

## 更新頻度の設計

**更新頻度が低いことが、このサイトの品質保証。**

ニュースサイトは毎日更新しないと死ぬため、載せるものが無い日も載せる。
その埋め草が「〇〇が実装に近い」になる。**更新義務が期待を生産する。**

| | ニュースサイト | holders CORE |
|---|---|---|
| 価値 | 新しさ | 構造 |
| 更新 | 毎日必須 | 変わった時だけ |
| 空白 | 埋める | そのまま置く |
| 読み方 | 毎日見る | 迷った時に見る |

### 各層の時定数

| 層 | 更新頻度 |
|---|---|
| 他チェーン横並び | 年単位 |
| FUEL | 月単位 |
| TIDE | 事件単位（年に数回） |
| ROOT | 動いた時だけ |
| ECHO | 事例確定時のみ。ほぼ固定 |
| 属性 | 不変 |

**サイトの大半はほとんど動かない。動かないから、動いた時に意味が出る。**

先月と同じなら「先月と同じです。潮を待つ時期です」とだけ出る。
その静けさが holder にとって一番の情報になる。
