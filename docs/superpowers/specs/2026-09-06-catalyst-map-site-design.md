# Catalyst Detailed Map — 独立サイトへの切り出し 設計
## 2026-09-06

`site/region.html` に全部入っている Catalyst の地図を、holders CORE の中の
独立したサイトとして切り出す。TOP を読み物本体にして、Catalyst 全体を
構造として捉えられるようにする。

前提の記録は `docs/data-notes/2026-09-06-handoff.md`。

---

## このサイトが存在する理由

誤差は二種類あって、性質が違う。

```
記録  ⇄  現実          誤差がある。サイトには埋められない。
                       報告が出ていることと、実際に何が起きたかは別。
                       ここはホルダー自身の判断になる。

記録  ⇄  ホルダーの認知   差がある。サイトが埋められるのは、こちらだけ。
                       記録は存在しているのに、投票した人の目に届いていない。
```

上を埋めようとした瞬間に「判定」になる。下は誰かが並べれば消える。
このサイトが存在する理由は、下の差が大きすぎることに尽きる。
上の誤差は、下が埋まって初めてホルダーが向き合えるようになるもので、
順番は逆にならない。

これが「判断しない」という作法の理由でもある。
判断しないのは慎重だからではなく、**判断は投票した側がするものだから**。

### 書けること / 書けないこと

| | 書ける | 理由 |
|---|---|---|
| 完了報告が出ているか | ○ | 記録に残る事実 |
| 記録が何日動いていないか | ○ | `stale` に収集済み |
| 事前評価と結果の関係 | ○ | 両方データにある |
| 投票後に議論されたか | × | 測る場所が用意されていない |
| 約束が果たされたか | × | 判定になる |
| DRep がどう判断したか | × | このサイトはデータを持たない |

「発信している project は評価に値する」——これは書かない。
報告書 1,761 件・動画 587 件・GitHub 23,890 本・証拠リンク 98% を
**並べるだけ**でいい。並べれば読む人が気づき、気づけば拡散できる。
サイトが「評価に値する」と書けば判定になる。書かなくても届く。

「配った後を見渡す場所が用意されていない」は書ける。
提案についての判断ではなく、制度についての記述だから。
しかも一次情報で裏が取れる —— projectcatalyst.io に個別ページはあっても、
Fund をまたいで採択後を並べた面は無い。完了報告 1,716 件は個別ページに散ったまま。
20分かけて個別ページを巡回して集める作り方そのものが、その場所が無いことの証拠。

## 構成

### 置き場

`site/catalyst-map/`（holders-core 内。別リポジトリにはしない）

`site/data`（52MB）は複製せず、`../data/` として共有する。
holders CORE の文脈（TIDE・台帳）はリンクで行き来できる状態を保つ。

トレジャリー Map 用の `site/maps/` のような器は**作らない**。
作ると決めていないものの場所を先に用意するのは先回りにあたる。
作ると決まったときに動かす。

### ページ

```
site/catalyst-map/
├─ index.html   TOP    読み物本体（後述の14節）
├─ map.html     地図   地球儀 + 左サイドバー（＝台帳）
└─ notes.html   記録の質  数が合わない / 事前の評価 / 価値の差 / 国の一覧(97行)
```

**台帳を独立ページにしない。** いまの実装では台帳＝地図の左サイドバーであり、
国→人物→プロジェクト→詳細のドリルダウンは地図の選択状態から出来ている
(`selectedIndexes()` / `personGroups()` / `renderPlist()` / `renderProject()` が
地図と同じ `state` を共有)。別ページに立てると二重実装になる。
「人物ランキングだけ見たい」は、地図で国を選ばない状態（＝世界）が既に満たしている。

**編集場所は一つ。** これが構成上の最優先。

### JS の分割

`region.js`（96KB）を割る。分割線は実装の分割線と一致させる。

```
map-globe.js   地球儀そのもの。データを知らない。
               orthographic / globePath / graticulePath / equatorPath /
               drawGlobe / setView / animateView / zoom 一式 / SPIN

map.js         Catalyst のデータを地球儀に載せる。
               state / selectedIndexes / personGroups / renderPlist /
               renderProject / renderSummary / buildMap / evidence / ask

notes.js       下段パネル。数が合わない / Fund の歩み / 価値の差 /
               事前の評価 / 国の一覧
```

`map-globe.js` を切るのは Catalyst 単体でも正しい分割（96KB を割る自然な線）。
将来トレジャリーを載せるときに無駄にならないのは結果であって、
そのために作るのではない。

### 二つのモード

`map.js` は一つの実装を二通りに呼ぶ。別実装は作らない。

```
mount(el, { mode: 'full'    })  → map.html
    地球儀 + 左サイドバー + 計器 + 操作一式

mount(el, { mode: 'display' })  → index.html のヒーロー
    地球儀だけ。自動回転・掴んで回せる・国を押すと国名と件数が浮く。
    renderPlist / renderProject を呼ばない。
```

`display` は `full` の機能を削った状態であって、縮小版の再実装ではない。
地球儀に手を入れれば両方に効く。

### CSS

`style.css`（60KB・holders CORE 全ページ共用）から地図分を
`site/catalyst-map/style.css` へ移す。
共通の骨（`.wrap` `.hero` `.figures` `.topbar`）は holders CORE 側に残し、
catalyst-map からも読む。二枚重ねにする。

これで青いネオン化のとき holders CORE を壊さずに済む。

## TOP の構成

三段。

```
[ 見る ]  ヒーロー ── MAP を三度見せる（国から / 人から / 一件まで）
[ 知る ]  分かること 5節 + 分からないこと 1節 + 歴史 + 相場 + 現在地
[ 使う ]  埋められないもの → 同じ構造が続いている → 問いで終わる
```

問いで始まり、問いで終わる。どちらも答えを書かない。

### ① ヒーロー

全幅・高さ 100vh の地球儀（`mode:'display'`）。自動回転。掴んで回せる。

```
あなたが投票した提案は、いま どうなっているか。

6年で 2,221 件が採択された。
完了 1,722 件。中止 269 件。報告は 1,716 件ぶん出ている。

それを見渡せる場所は、まだ無い。

[ 地図をひらく ]
```

四行目が全部を背負う。「無い」は否定ではなく現在地の記述で、
その次の行がボタンなので「無いものをいま開く」という動きになる。

### ② 計器

`11,385 / 2,221 / 1,722 / 269`（提案 / 採択 / 完了 / 中止）
地球儀の下に薄く重なる。スクロールで数え上がる。

### ③ MAP の見せ場 1 —— 国から入る

二度目の地図。画面半分で実物が動く。右に短い説明。
97 の国。押すとその国の採択が全部出る。

### ④ MAP の見せ場 2 —— 人から入る

三度目の地図。
5,699 人。関わった全部と、単独提案だけを切り替えられる。
51% が共同提案なので、人物別に足すと ADA が 2.0 倍・USD が 2.5 倍になる。
それも隠さず出す。

### ⑤ MAP の見せ場 3 —— 一件まで降りる

完了報告の動画 587 件。報告書 1,761 件。
約束と報告を左右に並べる。判断はしない。
`[ 地図をひらく ]` ← 二度目の誘導。読み物へ進まない人をここで地図に送る。

### ⑥ 完了報告は、存在する

```
1,716 / 1,722
98% に証拠リンク。GitHub だけで 23,890 本。
誰も並べていなかっただけ。
```

### ⑦ 採択された提案は、その期間 生きていたか

```
████░░░░░░░░████████░░░░████
採択      最初の提出      空白        完了

最後に記録が動いてから N 日を超えたものが N 件。
採択されて一度も動いていないものが N 件。

ただし、これは記録が動いた日であって、活動があった日ではない。
動いていたのに記録していないものと、
止まっていたものを、この線は区別しない。

区別できないまま、それでも線を引く。
引かなければ、誰の目にも入らないままになるから。
```

**数字は未測定。** `stale`（収集済み・未表示）の集計が要る。
実数が出てから文言を確定する。断定ではなく問いの形を保つこと。

### ⑧ 事前の評価は、その後を何も言い当てていない

```
3.67  =  3.67
中止 72 件      完了 732 件

6,908 件の 71% が 3.30〜4.00 に収まる（標準偏差 0.46）。
評価の労力は全部、金が動く前に置かれている。
```

### ⑨ 議論は、金が動く前にしかない

```
議論の記録は 6,908 件ある。すべて投票の前のものだ。

投票の後に、これがどう見られ、どう議論され、
どれだけ広まったかの記録は、どこにも無い。
拡散も議論も、測る場所が用意されていない。

このサイトが埋められるのは、
記録を目に留まる場所へ置くところまで。
```

⑧ と数字が重ならないようにする。⑧ は「評価が言い当てていない」ことを
中央値で示す節、⑨ は「投票後の記録が存在しない」ことを示す節。
⑨ で中央値を再掲しない。

推測で埋めない作法どおり、「議論されなかった」とは書かない。
**「測る場所が無い」と書く。**

### ⑩ 歴史 F1 ─ F15

横スクロールの帯。募集→レビュー→投票→結果→着手を同じ物差しで並べる。
右に予算と応募・採択数。

**採択率は単調に下がっていない。** 14% → 32.6%(F11) → 10.2%(F14)。
上下しながら下がっている、と書く。

### ⑪ 相場で $674万が動いた

```
−$674万
F10/F11 +28〜30%、F13/F14 −29〜31%。
全体の −6% は逆向きが打ち消し合った結果で、Fund 別に見ないと構造が消える。
```

### ⑫ 現在地 2026

移管 → 返還 → Pilot の3段の縦の流れ。

- 2026-02-24 運営が IOG から Cardano Foundation へ
- Fund 15（1,850万 ADA + 1,279万 USD + 25万 USDM）は distributed が全部ゼロ。
  返還がデータにそのまま出ている
- 2026-08 Catalyst Pilot（250万 ADA・10〜15件・成果連動 40/40/20）
- ADA 枠で F13 の 1/18.6。**「ADA 枠だけで比べて」と断る**
  （F13 は ADA 4,650万 + USD 4,878万の二本立てなので、単純比較にならない）
- Pilot の採択結果は「まだ起きていない」と書く

一次情報 3本を付ける（handoff に URL）。
TIDE と同じ作法の手動記録として置く。

### ⑬ このサイトが埋められないもの

```
報告が出ていることと、書かれたとおりに起きたことは別である。
その誤差は、ここでは埋められない。判断はあなたがする。

埋められるのはもう一つの差のほうだ。
記録は存在しているのに、投票した人の目に届いていない。
2,221 件を採択したのはホルダーで、
その後どうなったかを見る場所は、その手元に返ってきていない。

ここは、それを返す場所である。

[ 記録の質を見る → ]
```

ヒーローの問いに戻る。

### ⑭ 同じ感覚のまま、次が始まっている

```
Catalyst は 6年で 2,221 件を採択した。
完了 1,722 件、中止 269 件、報告 1,716 件。
報告は出ていた。目に留まる場所に無かっただけだ。
評価する構造は無いまま、資金は配られてきた。

いま、ホルダーは DRep に権限を預け、
DRep がトレジャリーの配分を決めている。

預けるときに見ていたものは、
Catalyst で投票するときに見ていたものと、同じではないか。
表明と、公約と、事前の評価。
その後を見る場所は、まだ返ってきていない。

─ いま、どう感じるか。

トレジャリーにも、同じ場所が要るのではないか。
```

**DRep について評価を書かない。** このサイトは DRep のデータを持たない
（holders CORE は別に DRep Terminal を持つ）。
言えるのは、Catalyst の記録と、それが同じ人たちの次の判断に
直結しているという接続まで。

**トレジャリー Map は問いのまま置く。** 作っていないものを
「作っている」と書けば、最後の一行で作法を破ることになる。

## デザインの方針

Apple のページ文法を、この題材に落とす。

- **1画面＝1つの事実。** 説明を積まない。巨大な数字か、1枚の図か、1行の文。
  スクロールが章の区切りになる
- **数字が主役で、文が従。** 「採択率が落ちた」と書かず、
  `32.6% → 10.2%` を画面いっぱいに置いて、下に小さく「F11 から F14 へ」
- **詳細はその場に展開しない。** 各章は結論だけ持ち、
  `詳しく見る ↓` で notes.html / map.html へ渡す。TOP は薄いまま長い
- **製品発表の順番。** 動いている実物（地球儀）を先に見せ、
  そのあとに歴史と発見、最後に現在地
- ⑥⑧⑪ が同じ形（大きな数字＋短い断定＋出典）で3回反復するのがリズム。
  ⑦⑩⑫ だけ形が違うので、そこが呼吸の切れ目になる
- **色相で優劣を作らない**（既存の作法）。⑪ の `−$674万` に赤を使わない
