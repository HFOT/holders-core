# 地域の層 — 設計判断と、公式データの状態
## Created: 2026-09-05

---

## 何を作ったか

`site/region.html`。Catalyst の採択がどの地域に落ちているかを一枚に置く欄。
projectcatalyst.io の [global map](https://projectcatalyst.io/global-map) と同じ題材を扱う。

## 追記（2026-09-05 同日・重要）

当初「提案ごとの位置は公開されていない」と判断していたが、これは誤りだった。
projectcatalyst.io の GraphQL（`/api/v1/graphql`）が、プロジェクト行そのものを公開している。
`country` / `continent` / `horizonGroup` / `tags` / `projectStatus` / 完了日 / 金額 / 投票結果が
プロジェクト単位で取れる。公式 global map の国別集計は、この行から作られている。

- `catalyst/projects.py` — 全 Fund × Challenge（151件）を回して収集。約2分
- `build-projects` — 採択分 2,317 行に落とし、台帳（Catalyst Explorer）と突き合わせて提案者名を付ける
  - 第一キー: projectcatalyst_io_link の一致（確実）
  - 第二キー: 同一 Fund 内のタイトル一致。同名が複数あれば採らない
  - 結果: 2,238 / 2,317 行（97%）で名前まで辿れた。辿れない行は名前なしのまま出す
- 金額は F9 以前が USD、F10 以降が ADA。**換算しない**。並べ替えは通貨ごとに行う
- これにより region.html は「国を押す → その国のプロジェクト一覧 → 金額順・完了順に並べ替え →
  個別の詳細（関わった人の名前・一次情報リンク）」まで降りられる。公式 global map にこの導線は無い

下の「最初に確認したこと」は記録として残す。Catalyst Explorer API 側に地域が無いのは今も事実。

---

## 最初に確認したこと

**台帳には地域の情報が一つも無い。**

Catalyst Explorer API の提案レコードを全項目走査したが、国・地域・座標に相当するフィールドは存在しない。
`users` にも `catalyst_profiles` にも無い。11,385 件のどれ一つとして地域に紐づけられない。

公式 global map のデータは Next.js の `__NEXT_DATA__` に丸ごと埋め込まれており、追加の API は無い。
持っているのは **国ごとの集計だけ**（`funded` / `completed` / `in_progress` / `cancelled` / `onboarding` と配分額）。
提案ごとの位置は公開されていない。

したがって「提案を地図上に置く」ことは、どちらの情報源からも**できない**。
推測で埋めることは設計原則に反するので、位置は作らない。**地域だけを扱う。**

---

## 採った方針

1. 公式 global map の配信データを第二の情報源として取り込む（`data/cache/global_map_raw.json`）
2. 値は一切書き換えない。名寄せも修正もしない
3. 検出できる欠陥には印を付け、行は一つも落とさずに出す
4. 台帳とは合算しない。別の計器として置く
5. 地図は国の単位までしか描かない。提案ごとの位置は持っていないので、点を打たない

## 採らなかった方針

- **提案から国を推定する** — 提案者名や本文からの推定は原則3（確定した事実だけ載せる）に反する
- **公式の壊れた行を直す** — どちらが正しいかを決める根拠が無い。直すと出所が消える
- **公式マップと同じ 3D グローブ** — 大陸を選んでからでないと全体が見えない作りで、
  そもそも大陸の値と国の合計が合わないことが構造的に画面に出てこない

## 公式データの状態（2026-09-05 取得時点）

配信データは 6 大陸・97 行の「国」。採択の合計は数え方で三通りに割れる。

| 件数 | どこの数か |
|---|---|
| 2,347 | 台帳の段階②以上（Catalyst Explorer API・全 11,385 件のうち） |
| 2,211 | 公式マップの大陸の値の合計（公式が画面に出している数） |
| 2,693 | 同じ配信データの国の行の合計 |

検出した欠陥（すべて機械的に検出。`catalyst/geo.py`）:

- **USA が North America と South America の両方に置かれている** — 同じ 458 採択・$32.3M が二重に数えられる。
  南米は大陸の値 177 に対して国の合計 629（差 +452）
- **`Czech Republic` と `Czech republic` が別の行** — 欧州は大陸の値 741 に対して国の合計 765（差 +24）
- **`North America` が国として記録されている** — 大陸名が国の一覧に入っている
- **`Texas` が国として記録されている** — 唯一、機械的に判定できないので `data/geo_notes.json` に手で置いた
- 大陸の値と国の合計が合わない大陸が 3 つ（欧州 +24 / 北米 +6 / 南米 +452）

公式マップは大陸を選んでから国を見る作りなので、これらは画面に出てこない。
また国名の重複は表示側で先勝ちの除外をしているため、二重計上そのものも見えない。

## 地図をどう描いたか

国境の形は Natural Earth（パブリックドメイン）の 1:50m 国境データを使い、
`catalyst/world.py` が SVG のパスに変換する。`site/data/world.json` は形だけを持ち、
Catalyst の数字は一切含まない。形と数字を別のファイルに分けているのは、
地図が変わっても数字が変わらず、数字が変わっても地図を作り直さずに済むようにするため。

- **投影**: Miller cylindrical。緯度は ±85 度で切る。南極は描かない（記録が無く、円筒図法で端が伸びきるため）
- **経度180度をまたぐ国**: ロシアとフィジーの環は +180 から -180 へ飛ぶ。そのまま平面に置くと
  地図を横断する帯になるので、飛んだところで環を切っている（`split_antimeridian`）
- **簡略化**: Douglas–Peucker。出力座標の丸め（小数1桁）で消える程度の細部だけを落とす
- **小さすぎる国**: 面が消えても落とさない。重心を残し、記録があるときだけ点を重ねて見つけられるようにする
- **濃さの段**: 1 から最大値までを対数で5段に切る。Catalyst の分布は一国（USA 458採択）に
  極端に寄っていて、等間隔だと下位が全部同じ段になり、順位（分位）だと上位が全部同じ段になる

### 見た目の設計（2026-09-05 改稿・同日再改稿）

このページの地図パネルだけ、サイトの単色文法から離れて固定の一枚絵にした（CORN の指示による）。
配色は公式マップの青×ピンクから意図的に離れ、**紙のアトラス**にした:
温かい紙色の海、白い大地、記録はティール（青緑）で深まり、アクセントはコーラル一色。
明るく、公式と並べても別物に見えることを優先した。

- 公式マップは土地が無地でピンだけが数字を持つ。ここでは**土地そのものが計器**であり、
  コーラルの大陸ピンは実数のカウントで、押すとその大陸へ寄る
- **一覧は二層**: 世界ビューでは国を調達金額（配分済み）順などで並べ、国を押すとその国の
  プロジェクト一覧に降りる。地図クリックと一覧クリックは同じ状態を動かす
- **国名の日本語⇄英語切り替え**を左バーに置いた。日本語表記は表示専用で、記録（英語）は書き換えない
- 一覧は左バー、国を押すと絞り込み、プロジェクトを押すと**左バーの右に詳細パネル**が滑り出す。
  地図はその右で生きたまま（Google マップの詳細カードと同じ文法）
- 基本は縮小埋め込み。「全画面」で画面いっぱいに切り替え、Esc で戻る
- 寄る動きは viewBox の補間（420ms・cubic ease-out）。ライブラリは使っていない
- **配分額モード**: 円の面積＝**申請額**、色の付いた扇＝そのうち**配分済みの割合**（円グラフ）。
  額と「実際に降りたか」を一つの図形で同時に読める。通貨は ADA / USD を混ぜず、選んだ側だけを描く
- **国ピン**: 寄ると、画面上で読める大きさ（26px 以上）の国にだけ数字ピンが出る。
  配分額モードでは円が額を語るので、ピンの数字は**採択数**を語る。押すとその国を選ぶ
- **経度180度の切り口**: 環を切っただけでは断片の始点と終点が直線で閉じ、地図を斜めに走る線が残る。
  切り口に経度 ±180 上の点（元の線分が経線と交わる緯度）を補い、端に沿って閉じるようにした。
  さらに、閉じた環の始点が本土の途中にある場合は本土が前半と後半に割れるため、
  最後の断片を最初の断片に繋ぎ直す（ロシアが白抜け＋斜め横断線になる原因だった）。
  検証: 全240ヶ国の全サブパスで、端以外の長い閉じ線がゼロであることを機械確認
- **キャッシュ**: CSS / JS は中身のハッシュを ?v= に付けて参照する。生成データは region.js 内の
  版文字列（V）で読み直させる。build し直したら V を上げること
- **計器タブは地図の左上に浮かべる**: 全画面でも切り替えられるようにするため
- **実装の罠**: ドラッグ用の `setPointerCapture` は click イベントの行き先を SVG 本体に
  付け替えるため、クリック判定は `pointerup` 側で行う（pointerdown 時の target を覚えておく）。
  フォーカスの四角い枠は `:focus { outline:none }` で消し、キーボード時だけ `:focus-visible` で示す

### 地図ライブラリとタイルを使わなかった理由

OpenStreetMap 系のタイル地図（MapLibre 等）も検討したが、採らなかった。

- 手元にあるのは**国ごとの集計だけ**で、街路や住所の精度は一切無い。
  街路が描かれた地図に国単位の集計を載せると、無い精度があるように見える
- site の依存はゼロで、GitHub Pages に置いてオフラインでも開ける。
  タイルサーバーへの実行時通信が入ると、その性質が消える
- 拡大縮小と移動は SVG の viewBox を動かすだけで足りる。ライブラリは要らない

住所や施設の単位で記録を持つ日が来たら、この判断は見直す。今は持っていない。

### 地図に載らないもの

- **Gibraltar** — 1:50m の国境データに面が無い。採択2件。地図の下に文で出している
- **North America / Texas** — 国ではない。地図に置く場所が無い
- **台帳 11,385 件のうち 9,038 件** — 採択されておらず、公式マップの対象外。地図に一つも載らない

## 実装

- `catalyst/geo.py` — 取得と整形。値は変えず、印だけ付ける
- `data/geo_notes.json` — 自動判定できない注記だけを置く手動記録（現在は `texas` の 1 件）
- `catalyst/build.py` — `harvest-geo` / `build-geo` を追加。`build-geo` は `site/data/meta.json` を必要とする
- `catalyst/world.py` — 国境の形を SVG のパスに変換する。Catalyst のデータは入らない
- `site/region.html` / `site/region.js` — 表示。上に世界地図、下に大陸ごとの帯の一覧
- 帯の基準は世界全体の最大値。大陸をまたいで比べられるようにするため
- 地図の拡大縮小・移動・大陸への寄せ・国を押したときの数字は、すべて自前の SVG 操作

区別は線種で行う。実線＝そのままの記録／破線＝二重に数えられている／点線＝国ではない。
色相で優劣を作らない（既存ページと同じ文法）。
