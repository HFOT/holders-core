# 金が動いたあと — 状態フラグの層
## Created: 2026-09-05

---

## なぜ作ったか

Catalyst の記録は「誰がいくら得たか」で止まっている。
その後どうなったかを誰も見ていない、というのが出発点だった。

調べたところ、**記録は存在するのに誰も見ていない**状態だった。

---

## 見つけた情報源

### 1. projectcatalyst.io の個別プロジェクトページ

`__NEXT_DATA__` に埋め込まれている。2,317件ぶん取得した。

- `milestoneDetail.startDate` … 開始日（ただし後述の理由で使わない）
- `milestoneDetail.milestones[]` … 各マイルストーンの題・計画月・計画日・状態・金額
- `completed.date` / `completed.reportUrl` … **完了報告の日付と現物へのリンク**
- `lastUpdated.days` … 最後に記録が動いてから何日

### 2. マイルストーンモジュールの公開データ

`milestones.projectcatalyst.io` は Supabase を使っており、公開ページが読み取り専用の
匿名キーを配っている（`env.js`）。その先の公開テーブルが読める。

| テーブル | 件数 | 中身 |
|---|---|---|
| proposals | 1,146 | 予算・配分額・MS数・状態 |
| soms | 15,749 | 各MSの成果物・成功基準・証拠・計画月（**改訂履歴**） |
| signoffs | 10,257 | **承認の記録。created_at が実際の承認日** |
| poas | 8,712 | **Proof of Achievement（達成の証拠の現物）** |
| change_request | 363 | 計画変更の申請 |

`users` と `challenges_users` は 0 件で読めない。**誰が承認したかは追えないし、追わない。**
個人が保護されている境界であり、越えない。

これは公式に案内された API ではない。公開ページが使っている経路をそのまま辿っている。
負荷をかけないよう間隔を空け、一度取ったら取り直さない。出典は必ず明記する。

## 判定の基準 — Catalyst Japan から引き継いだもの

[Catalyst Japan](https://hfot.github.io/Catalyst-Japan/) に、日本 130 件を手で追って
作られた状態フラグの実装がある。世界 2,317 件へ、その考え方をそのまま引き継いだ。

### 起点は Fund の採択結果発表日

**モジュールの `starting_date` は使わない。**
620 件で初回承認日より後に置かれており、実際の着手日ではない。
承認の 43% が「開始日より前」になってしまう。

過去の Fund は資金を一度に受領していたため、**採択決定日が実質の資金受取日**にあたる。
Catalyst Japan もここを起点にしていた（`FUND_RESULT_DATES`）。

各マイルストーンの期限も `採択決定日 + 計画月数`。超過はそこから数える。

### 終点は三段構え

1. マイルストーンがあり完了 … 最後の承認日
2. マイルストーンが無く完了 … 完了報告（close-out）の日
3. まだ完了していない … 今日

2 の道があるので、制度が始まる前の Fund でも期間そのものは測れる。
ただし**長期化のフラグは、マイルストーンの記録がある案件にだけ立てる**。
記録が無ければ途中で何が起きたかを誰も追えておらず、期間の長さに意味を持たせられない
（Catalyst Japan も `_skipDur = !CJ_MILESTONES[id]` で同じ切り分けをしている）。

### しきい値

`data/fund_dates.json` に置く。Catalyst Japan の値をそのまま使う。

| フラグ | 条件 |
|---|---|
| 🚫 停止 | 中止 + 資金受領あり |
| 💧 不発 | 中止 + 資金未受領 |
| ⚠️ 期限超過 | 進行中 + 未承認MSが計画から3ヶ月超過 |
| ⏳ 進行中ギャップ | 進行中 + 承認の間が6ヶ月以上 |
| ↔️ 過去ギャップ | 完了 + 承認の間が8ヶ月以上 |
| ⌚ 期限超過で完了 | 完了 + 計画から6ヶ月以上遅れて完了 |
| 2️⃣ 長期化 | 採択から2/3/4年以上 |

止まったもの（停止・不発）に、遅れの旗は重ねない。二重に責めない。
ただし期間の長さは状態と別の軸なので、条件を満たせば残る。

## データの限界 — 隠さずに書くこと

### `soms` は承認されたものしか登録されない

5,039 組（改訂を畳んだ後）のうち 5,008 が承認済み（99%）。
まだ提出されていないマイルストーンは、行そのものが存在しない。

このため **⚠️ 期限超過はほとんど立たない**（世界で3件）。
Catalyst Japan が 220 件検出できていたのは、130 件を手で追って未提出も把握していたため。
世界データでは原理的に取れない。

**「⚠️ が立っていない＝遅れていない」ではない。** 表示するなら必ずそう書く。
実質の代替は ⏳ 進行中ギャップ（223件）で、こちらは承認日の実在する差から出している。

### `soms` は改訂履歴である

同じ (proposal_id, milestone) に最大 27 版が積まれる。
**id が最大のもの＝最新版だけを採る。** 全版を束ねると、古い版の承認で
最新版まで承認済みに見えてしまう。

## 世界 2,317 件での結果（2026-09-05 時点）

| フラグ | 件数 |
|---|---|
| 🚫 停止（資金受領後に終了） | 247 |
| ⏳ 進行中ギャップ | 223 |
| 2️⃣ 長期化 | 169 |
| 💧 不発 | 21 |
| ⌚ 期限超過で完了 | 8 |
| ⚠️ 期限超過 | 3（上記の限界による） |
| ↔️ 過去ギャップ | 2 |

超過率（計画の何倍かかったか）: 1,108 件で測定。
中央値 0.2 倍、**1倍超が 30%**、2.5倍超が 166 件、最大 23.6 倍。

承認の実績: 初回承認 → 最終承認の中央値 239 日（7.9ヶ月）、最長 913 日。

### 事前評価は、その後を何も言い当てていない

コミュニティレビューのスコア（整合性・実現可能性・監査可能性）と結末の関係:

| その後 | 件数 | 事前スコア平均 | 中央値 |
|---|---|---|---|
| 完了 | 732 | 3.64 | 3.67 |
| 進行中 | 205 | 3.60 | 3.67 |
| 中止 | 72 | 3.52 | 3.67 |

**中止と完了で中央値が同じ。** しかもスコア自体が機能しておらず、
6,908 件の 71% が 3.30〜4.00 に収まる（標準偏差 0.46）。

評価の労力はすべて金が動く前に置かれ、動いた後はゼロ。
この層は、その空白に数字を入れるために作った。

## 約束された価値と、受け取った価値

Catalyst は ADA 建てで採択し、マイルストーンの承認ごとに支払う。
採択から支払いまでの間に相場が動けば、同じ ADA 額でも受け取った価値は変わる。
**この差は提案者の成果とも、審査の判断とも関係がない。**

### 測る範囲を切った

**マイルストーン制の Fund（10 以降）で、すべてのマイルストーンが承認済みの案件だけ**を測る。

- それ以前は受取日が記録に無い。いつの時価で測ればよいか決められない
- 途中の案件も測らない。残りをいつ受け取るか分からない

「分からない」を「変化なし」にしない。1,068 件が対象になった。

### 結果（2026-09-05 時点）

| Fund | 件数 | 約束（採択時） | 受取（承認日） | 差 |
|---|---|---|---|---|
| 10 | 191 | $13,513,428 | $17,360,287 | +28% |
| 11 | 300 | $24,658,226 | $32,033,183 | +30% |
| 12 | 255 | $20,189,754 | $19,279,795 | −5% |
| 13 | 196 | $47,291,474 | $33,634,865 | −29% |
| 14 | 126 | $10,935,573 | $7,537,131 | −31% |
| **合計** | **1,068** | **$116,588,455** | **$109,845,261** | **−6%** |

**全体の −6% は、逆向きの動きが打ち消し合った結果**である。
最も上がった Fund と最も下がった Fund の間には 61 点の開きがある。
全体の平均だけを出すと、この構造が消える。Fund ごとに並べること。

### 但し書き（必須）

出す値は「その日の終値で計算するといくらか」であって、**実際の換金額ではない**。
提案者がいつ換金したか（今も持っているか）は記録に無い。この一文を外して出さない。

価格は Binance ADAUSDT 日足の終値（2021-01-01 以降）。取引所の値であり公式の指標ではない。
CoinGecko・Coinpaprika の無料枠は直近1年しか遡れず、Fund 10（2023年）に届かなかった。

## 事前の評価

投票の前に、コミュニティのレビュアーが提案書に付ける点数（整合性・実現可能性・監査可能性、
各5点満点）。Catalyst Explorer API に 6,908 件ぶんある。

| その後 | 件数 | 事前スコアの平均 | 中央値 |
|---|---|---|---|
| 完了 | 732 | 3.64 | **3.67** |
| 進行中 | 205 | 3.60 | **3.67** |
| 中止 | 72 | 3.52 | **3.67** |

**中止と完了で中央値が同じ。** 点数そのものの散らばりも小さく、
6,908 件の 71% が 3.30〜4.00 に収まる（標準偏差 0.46）。

この欄は点数の当否を論じない。評価の労力がどこに置かれているかを、数字のまま示す。

## 日本語訳

約束と報告の本文 12,930 本を機械翻訳（LibreTranslate の公開インスタンス）。
13,285 本のうち 99% が日本語化された（未訳 35 本）。

- **原文は書き換えない。** 訳は `site/data/evidence-ja/` に別ファイルで置く
- 画面では訳を主にし、原文は `▸ 原文` で必ず開ける
- 「機械翻訳なので誤りうる」を画面に明記する

一度訳したものは `data/cache/evidence_ja.json` に残る。同じ文は二度訳さない。
途中で止めても続きから始まる。

## 質問する道具

各マイルストーンに「この2つについて質問する」を置いた。
A（提案で約束したこと）と B（完了報告で報告されたこと）を AI に渡す。

**こちらからは何も指示しない。** 何を聞くかは読む人が決める。
`ask.js` に「評価して」「判定して」に類する語を書かない。渡すのは A と B が何であるかの説明だけ。

- 鍵は読む人の端末（localStorage）にだけ置く
- 答えは保存しない。holders CORE の記録ではない
- 無料の鍵（Groq）で使える

判定をサイトの記録にしない、という線を引いた。誤判定が公開の評価になることを避けるため。

## Catalyst Japan の実装から引き継いだもの（2026-09-06）

[Catalyst Japan](https://hfot.github.io/Catalyst-Japan/) は 142 関数・438KB あり、
日本 130 件を手で追って練られている。世界データへ移せるものを選んで取り込んだ。

### 1. 価格は前後から補間する

Japan の `nearestPrice` は、記録の無い日を**前後の記録から直線で按分**する。

こちらは当初「直前まで最大7日遡る」実装だったが、それでは休みを挟んだとき古い側へ寄る。
承認日は平日に集中するので実際に差が出る。前後を見て距離で按分する形に直した
（`prices.price_on`）。前後どちらかしか無ければその値、どちらも 7 日より遠ければ諦める。

### 2. 中止した案件が資金を受け取っていたか

```
Fund 9 以前 … 採択時の一括払い。記録上 0 でも受領済み
Fund 10 以降 … 分割払い。配分額で判断する
```

Japan の `_dnfReceivedFunds` と同じ切り分け。当初は配分額だけで判定しており、
**Fund 9 以前の 11 件を「不発」と誤っていた**。

修正で 停止 247 → 258、不発 21 → 10 になった。

### 3. 金額は二段で出す

Japan の `fmtDual` は主表示と副表示を常に組にする（`3.3M ₳` と正確な額）。
大きな額を生の数字で出すと桁が読めず比べられない。

`compactAmt` / `dualAmt` を作り、国・人物の行に適用した。
**ADA と USD は換算しない**ので、副に置くのは同じ通貨の正確な額にした
（Japan は法定通貨へ換算しているが、こちらは通貨を混ぜない方針を優先）。

### 引き継がなかったもの

**役割の3階層**（`mainUsdK` / `coUsdK` / `teamUsdK` ＝ メイン提案者・共同提案・名義）。
Japan は 130 件を手で判別しているが、**Catalyst Explorer の `users` に役割の記録は無い**。
名前と ID だけである。並び順に意味がありそうに見えるが保証が無いので、推測しない。

代わりに、記録から確実に取れる区別だけを使う:

- **関わったすべて**（共同提案を含む。他の人にも同じ額が計上される）
- **単独提案だけ**（その人だけの額。足し合わせられる）

共同提案は 2,317 件中 1,193 件（51%）。人物別に足し合わせると
**ADA が 2.0 倍、USD が 2.5 倍**になる。注記だけでは足りないので、
行ごとに `※` を付け、件数も添えた。

## 実装

- `catalyst/milestones.py` — 個別ページからマイルストーンと完了報告を集める
- `catalyst/module.py` — マイルストーンモジュールの公開データ。改訂を畳む
- `catalyst/flags.py` — 状態フラグの判定。しきい値は `data/fund_dates.json`
- `catalyst/evidence.py` — 約束と報告を並べる。HTML の断片を外して読める文章に戻す
- `catalyst/prices.py` — ADA の日次価格（Binance ADAUSDT 日足）
- `catalyst/value.py` — 約束された価値と受け取った価値。測る範囲を切る
- `catalyst/scores.py` — 事前スコアと結末の対応
- `catalyst/translate.py` — 日本語訳。原文は書き換えない
- `site/ask.js` — 質問する道具。指示を書かない
- `data/fund_dates.json` — Fund ごとの提出/投票/結果発表日、ADA 価格、しきい値。
  API には無い値であり、Catalyst Japan から引き継いだ手動記録

評価はしない。良し悪しを決めない。遅れている日数は判定ではなく、計画と記録の差である。
